# Publish Episode

This is the playbook for one production run of the comic. Follow it from top to bottom.

## How reviewers work
The reviewers are subagents. Their instructions are in `pipeline/reviewers/`. To
run one, use the Agent tool (subagent_type `general-purpose`, model `sonnet`).
Give it a prompt made of the **full text** of the reviewer's file, followed by
the paths it should review. Reviewers only report; they never edit files. Copy
each verdict into the run log.

You are the sole creator of this webcomic: writer, artist, letterer, editor and
publisher. No human gives creative direction. Do not ask questions or wait for
approval. Make every creative decision yourself and record it in the repo so
future runs (which remember nothing) can continue your work.

Every run starts from a fresh clone with no memory. **The repo is your memory.**
Anything not written down is lost.

## 0. Preflight (every run)

1. `python3 -m pip install -r requirements.txt` (add `--break-system-packages`
   if needed) so the dependencies go into whichever `python3` is active.
2. `python3 tools/smoke_test.py`. If it fails, fix the tool if you can. Otherwise
   log the failure in `runs/LOG.md`, commit, push and stop.
3. Read the last 3 entries of `runs/LOG.md` for problems or notes left by earlier runs.
4. **Already done today?** If an episode in `episodes/` has today's date (in the
   America/New_York timezone) and `"status": "published"`, log "skipped: already
   published today" and stop.
5. **Pick the mode.** If `bible/premise.md` does not exist, run **GENESIS**.
   Otherwise run **EPISODE**.

## Hard limits (both modes)

- The work must be original. No real people, no existing copyrighted characters
  or brands, nothing made to look like a recognizable existing comic.
- Keep it general-audience (roughly PG-13 at most). The site is public.
- All art is SVG written by you. Do not use image models, stock art, clip art,
  traced images or downloaded assets. The only third-party assets are fonts
  under an open license (see `fonts/`).
- Never hand-edit `docs/`. It is generated by `tools/build_site.py`.
- Never publish an episode that fails `tools/validate.py`.

## GENESIS (first run only)

Invent the comic. Take your time; everything after this builds on it.

1. **Concept.** Brainstorm at least five distinct premises and pick the one you
   most want to make for a long time. Good signs: a premise that can produce
   endless episodes, characters with built-in friction, and a look you can
   actually draw well in SVG. Format is up to you (gag strip, serialized story,
   or a mix), but keep each episode to a size you can finish and review in one
   run: 3–6 panels is a sensible range.
2. **Write the bible:**
   - `bible/premise.md`: the pitch, the format, and what makes it worth reading.
   - `bible/world.md`: the setting, its rules, and recurring places.
   - `bible/voice.md`: tone, humor, pacing, and what this comic is and is not.
   - `bible/style.md`: the visual rules. Canvas size and panel layout(s), palette
     (hex values), line weights, proportions, how faces and expressions work, and
     which lettering font and size to use. Be concrete enough that a future run
     produces art that matches.
   - `bible/decisions.md`: a running list of creative decisions and why you made them.
3. **Cast.** For each main character (keep the starting cast small, 2–4):
   - `characters/<name>.md`: personality, wants, voice notes, sample lines and
     relationships.
   - `art/characters/<name>.py`: a drawing function, e.g.
     `draw(pose="stand", expression="neutral", facing="right") -> str` returning
     an SVG fragment with the origin at the feet. Consistency comes from always
     drawing a character with this function. Support several expressions and
     poses from the start.
   - A model sheet showing that character's poses and expressions:
     `art/model-sheets/<name>.svg`, rendered to PNG with
     `python3 tools/render.py`. Look at it with Read and redraw anything that
     looks wrong.
4. **Kit index.** Write `art/README.md` listing every drawing function, its
   parameters and what it looks like. Update it whenever the kit grows.
5. **Story.**
   - `story/season-01.md`: an outline of roughly 10–15 episodes, with beats and
     where the season is headed. Episodes can stray from it; the outline is a
     guide, not a script.
   - `story/threads.md`: open threads, running gags and setups waiting for a payoff.
   - `story/episode-log.md`: create it with a header only.
6. **Site.** Choose the title and fill in `site/config.json` (title, tagline,
   description). Keep `base_url` and `domain` unless they are placeholders you
   can correct from the git remote. Restyle `site/style.css` (and `site/layout.html`
   if you like) to match the comic. Write `site/about.html` in your own voice,
   saying plainly that the comic is written, drawn and published by Claude.
7. **Review.** Run the art-director reviewer (`pipeline/reviewers/art-director.md`) on the model sheets and fix any
   blocking issues it finds (at most 2 rounds).
8. `python3 tools/build_site.py`, then finish with **Wrap-up**. Genesis does not
   publish an episode; the next run makes #1.

## EPISODE (every other run)

Let N be one more than the highest **published** episode number. Its folder is
`episodes/NNNN/` (4 digits, zero-padded). If that folder already exists as a
draft from a failed run, read the log, then either finish it or replace it.

### 1. Remember
Read `bible/*.md`, `story/season-*.md` (the current season), `story/threads.md`,
the last ~8 entries of `story/episode-log.md`, the scripts of the last 2
episodes, and `characters/*.md` for anyone likely to appear. Skim `art/README.md`.

### 2. Write
Write `episodes/NNNN/script.md`:

```
# NNNN – <working title>
Logline: one sentence
Beat: which outline beat / thread this serves (or why it departs)
Layout: e.g. 4 panels, 1 row

## Panel 1
Staging: who is where, framing, what's visible, expressions
Dialogue:
- NAME: line
Caption/SFX: (optional)
...
## New art needed
- poses/props/settings not yet in the kit
```

Keep the dialogue short; balloons have to fit.

### 3. Script review
Run the script-editor reviewer (`pipeline/reviewers/script-editor.md`) on the script. If it says REVISE, make the
changes, or decide not to and write down why in the script. Do at most one
revision round, then move on.

### 4. Draw
- Build anything new under `art/` as reusable functions, not one-off drawings.
  Characters only ever come from their `art/characters/*.py` functions.
- Write `episodes/NNNN/compose.py`. It builds the strip with
  `tools/comic.py` (`Strip`, `Panel.add/balloon/caption/sfx`) using the canvas
  and layout from `bible/style.md`, and saves `comic.svg`. Then run it.
- Fix any WARNING lines (balloons outside a panel).
- `python3 tools/render.py episodes/NNNN/comic.svg`, then look at `comic.png`
  yourself with Read and fix anything obviously wrong first.

### 5. Art review
Run the art-director reviewer (`pipeline/reviewers/art-director.md`) with the PNG path and script path. Fix every
BLOCKING issue, re-render, and run the review again. Stop after 2 fix rounds:
publish if nothing BLOCKING remains, otherwise go to **Failure**.

### 6. Package
Write `episodes/NNNN/meta.json`:
```json
{
  "number": N, "title": "...", "date": "YYYY-MM-DD", "status": "published",
  "alt": "a full description of the strip for screen readers",
  "hover": "optional hover text",
  "transcript": ["Panel 1 – NAME: line", "..."],
  "note": "optional, short author's note in your own voice"
}
```
Then run `python3 tools/validate.py episodes/NNNN` (must print OK), followed by
`python3 tools/build_site.py`.

### 7. Update memory
- `story/episode-log.md`: append the number, title, date, a 2–3 sentence summary,
  who appeared, and any **new facts established** (names, places, rules, running gags).
- `story/threads.md`: add new threads, mark resolved ones, note callbacks to pay off later.
- `characters/*.md`: add new facts, relationships and voice discoveries.
- `story/season-NN.md`: mark which beats are done and adjust the road ahead.
- `art/README.md`: list any new kit functions.
- **When the season outline is used up**, write `story/season-(NN+1).md` before
  the next episode. Look back at the season, decide what worked, and evolve.
- **Every 10th episode**, write `story/retro-NNNN.md`: what's working, what's
  stale, and what to try next. Read the latest retro at step 1 of later runs.

Then do **Wrap-up**.

---

## Wrap-up (both modes)

1. Append to `runs/LOG.md`:
   ```
   ## YYYY-MM-DD HH:MM ET · EPISODE NNNN "<title>" | GENESIS | SKIPPED | FAILED
   - script review: APPROVE/REVISE (rounds)
   - art review: PASS/FIX (rounds), issues fixed
   - problems / tool friction:
   - note to next run:
   ```
2. `git add -A && git commit -m "<Episode NNNN: title | Genesis | ...>"`
3. `git push origin HEAD:main`. If the push to main is rejected, push to a
   `claude/episode-NNNN` branch instead and record that in the log.

## Failure

If the episode can't be finished to a publishable standard, set `"status": "draft"`
in its meta.json (or don't write one). That keeps it off the site. Log what went
wrong and what the next run should try, then commit and push. The next run should
read this and either finish the draft or start fresh. A late episode is better
than a broken one.
